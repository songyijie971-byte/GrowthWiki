# 02_TechDocs

这里保存技术文档的整理笔记，只放已经阅读、实践或理解后的 Markdown。

## 放什么

- 工具文档整理
- 框架文档整理
- 工程方法总结
- 使用方式
- 踩坑点
- 配置经验

## 不放什么

- 未读收藏链接
- PDF/DOCX 原文
- 聊天杂物
- 生活记录
- 职业规划
- 导师资料

## 笔记要求

每篇技术文档笔记应至少包含：

- `What It Is`
- `Core Ideas`
- `How To Use`
- `Engineering Notes`
- `Common Pitfalls`
- `Related Concepts`

每篇技术文档建议链接 1-3 个概念。概念页负责把技术文档和论文连接起来。

## 命名规则

- 文件名使用短知识主题名，不直接复制公众号标题、宣传标题或 PDF/DOCX 原始文件名。
- 文件名建议控制在 10-20 个汉字左右，能表达核心主题即可。
- 原始标题必须保留在笔记 `Metadata` 的 `原始标题` 字段。
- 节点标题必须保留在笔记 `Metadata` 的 `节点标题` 字段。

推荐：

```text
LBM多任务灵巧操作评估.md
PRTS-VLA目标可达性.md
MuJoCo-IsaacSim仿真环境对比.md
```

不推荐：

```text
Science Robotics封面研究：近5万次测试，定义多任务灵巧操作的真实边界.md
TeleAI最新PRTS基座模型：把目标感写进VLA，让机器人知道距离目标还差多远.md
```
