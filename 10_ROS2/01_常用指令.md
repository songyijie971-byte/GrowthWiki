# 常用指令

> [!tip] 使用范围
> “Python 功能包运行闭环”是当前 `demo_python_pkg` 项目的操作流程；其余命令是按需使用的环境、文件操作或检查工具，并非每次运行项目都要全部执行。

## Linux 文件操作

按需使用，不属于 ROS 2 项目的固定运行流程。

```bash
pwd                         # 查看当前位置
ls                          # 查看当前目录内容
cd 文件夹                    # 进入文件夹
cd ..                       # 返回上一级
mkdir 文件夹                 # 创建文件夹
touch 文件                   # 创建空文件
nano 文件                    # 在终端中编辑文件
cat 文件                     # 查看文本文件内容

cp 原文件 新文件             # 复制
mv 原名称 新名称             # 移动或重命名
rm 文件                     # 删除文件，谨慎使用
```

## 软件安装

仅在需要安装或更新软件时执行。

```bash
sudo apt update             # 更新软件列表
sudo apt install 软件名      # 安装软件
```

## Python 功能包运行闭环

当前项目：工作空间 `~/chapter2_ws`，功能包 `demo_python_pkg`，程序入口 `python_node` 和 `book_subscriber`。

只记流程：**加载 ROS 2 → 创建一次 → 编译 → 加载工作空间 → 运行 → 按需检查**。

### 第一次创建

```bash
source /opt/ros/humble/setup.bash  # 加载 ROS 2 Humble 环境
mkdir -p ~/chapter2_ws/src         # 创建工作空间和 src 目录
cd ~/chapter2_ws/src               # 进入功能包源码目录
ros2 pkg create demo_python_pkg --build-type ament_python --license Apache-2.0  # 创建 Python 功能包
```

> `ros2 pkg create` 只在第一次创建功能包时执行。

### 修改代码后

```bash
source /opt/ros/humble/setup.bash                 # 新终端先加载 ROS 2 环境
cd ~/chapter2_ws                                  # 回到工作空间根目录
colcon build --packages-select demo_python_pkg    # 只编译指定功能包
source install/setup.bash                         # 加载本工作空间的编译结果
ros2 run demo_python_pkg python_node              # 运行功能包中的节点
```

> 类比：`colcon build` 把书放进书架，`source` 告诉当前终端书架的位置，`ros2 run` 再从书架里取书。

### 在另一个终端检查节点

以下命令用于检查，不是启动项目的必需步骤。

```bash
source /opt/ros/humble/setup.bash             # 加载 ROS 2 Humble 环境
source ~/chapter2_ws/install/setup.bash        # 加载工作空间环境
ros2 node info /python_node                    # 查看节点的发布、订阅等接口
```

## book Topic 发布订阅运行闭环

完整原理和代码见 [[10_ROS2/02_概念卡片/Topic（话题）|Topic（话题）]]。

> [!important] 只记两条
> 1. 修改代码或 `setup.py` 后，重新编译。
> 2. 每个新终端都要重新加载 ROS 2 和工作空间环境。

### 终端 1：语法检查、编译并启动发布节点

```bash
python3 -m py_compile ~/chapter2_ws/src/demo_python_pkg/demo_python_pkg/python_node.py
python3 -m py_compile ~/chapter2_ws/src/demo_python_pkg/demo_python_pkg/book_subscriber.py
python3 -m py_compile ~/chapter2_ws/src/demo_python_pkg/setup.py

source /opt/ros/humble/setup.bash
cd ~/chapter2_ws
colcon build --packages-select demo_python_pkg
source install/setup.bash
ros2 run demo_python_pkg python_node
```

`py_compile` 没有输出表示语法通过；它是排错工具，不是每次运行的必需步骤。

### 终端 2：启动订阅节点

```bash
source /opt/ros/humble/setup.bash
source ~/chapter2_ws/install/setup.bash
ros2 run demo_python_pkg book_subscriber
```

### 终端 3：检查 Topic

```bash
source /opt/ros/humble/setup.bash
source ~/chapter2_ws/install/setup.bash
ros2 topic echo /book                  # 查看实际消息
ros2 topic info /book                  # 查看消息类型及发布、订阅数量
```

检查命令一次执行一条；持续输出时按 `Ctrl+C` 停止，再执行下一条。

## 检查节点和 Topic

以下是通用检查命令，按需执行；最后一条只针对 turtlesim。

```bash
ros2 run 功能包 程序名                   # 运行指定功能包中的程序
ros2 node list                         # 查看运行中的节点
ros2 node info /节点名                  # 查看节点的接口
ros2 topic list                        # 查看当前Topic
ros2 topic info /turtle1/cmd_vel       # 查看速度指令Topic的发布者和订阅者
```

## Git 提交并上传 GitHub

前提：当前 Ubuntu 已完成 GitHub 身份认证，并且本地仓库已关联远程 GitHub 仓库。

```bash
gh auth status                         # 检查“我是谁”
git remote -v                          # 检查“上传到哪里”
```

以后每次修改代码后执行：

```bash
cd ~/chapter2_ws
git status                              # 查看修改
git add src                             # 暂存源码
git commit -m "说明这次修改了什么"         # 保存本地版本
git push                                # 上传到 GitHub
```

只记顺序：**查看修改 → 暂存代码 → 保存版本 → 上传 GitHub**。

如果还修改了其他文件，按需添加，例如：

```bash
git add README.md .gitignore
```

`build/`、`install/` 和 `log/` 已由 `.gitignore` 忽略，不需要提交。

## 使用提示

- `Tab`：自动补全。
- `Ctrl+C`：停止当前程序。
- `命令 --help`：查看该命令的参数和用法。
- 教材命令前面的 `$` 不需要输入。
